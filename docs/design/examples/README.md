# Platform CR — examples and field reference

This directory holds the **annotated field reference** for the `Platform` CRD
([`platform-cr-reference.yaml`](./platform-cr-reference.yaml)) plus a handful of worked
shapes. The reference yaml exercises the **full shipped `otilm.com/v1alpha1` surface**
(verified against `api/v1alpha1/platform_types.go` + `common_types.go`); each block is
tagged `[IMPLEMENTED]` or `[NOT IMPLEMENTED]` (a clearly-marked design target).

> **For working, copy-pasteable examples that pass validation, use
> [`config/samples/`](../../../config/samples/)** — `platform_quickstart.yaml`
> (everything-managed, apply-and-go), `platform_minimal_external.yaml` (the smoke test),
> `platform_full.yaml` (the kitchen-sink of shipped fields), and the per-feature variants.
> The end-user walkthrough is the [getting-started guide](../../platform.md).

**Rules of the road:** required = `database` + `messaging` (each `external` *or* `managed`).
Secrets are always a `…SecretRef` to a `Secret` — never inline. `external` = you bring the
connection + a credentials Secret (no upstream operator). `managed` = the operator provisions
it via an upstream operator (CloudNativePG / RabbitMQ / Keycloak), which *generates* the
credentials.

## Minimal — fully managed

```yaml
apiVersion: otilm.com/v1alpha1
kind: Platform
metadata: { name: ilm, namespace: ilm }
spec:
  database:  { mode: managed }
  messaging: { mode: managed }
```

Secrets you create: none (generated by the upstream operators). Prerequisites: CloudNativePG,
the RabbitMQ Cluster + Messaging Topology operators.

## Minimal — external (BYO)

```yaml
spec:
  database:  { host: postgres.example.com, name: ilmdb, credentials: { secretRef: ilm-db } }
  messaging: { host: rabbitmq.example.com, virtualHost: ilm, credentials: { secretRef: ilm-messaging } }
```

Secrets you create: `ilm-db`, `ilm-messaging`. Prerequisites: none beyond the ILM operator
(plus an ingress controller / cert-manager if you add an `edge`).

## High availability — one flag

```yaml
spec:
  highAvailability: { enabled: true }     # multi-replica + PDB + anti-affinity on the STATELESS tier
  database:  { mode: managed, managed: { instances: 3 } }
  messaging: { mode: managed, managed: { replicas: 3 } }
```

Stateless tier → multi-replica + PDB + anti-affinity. Stateful managed-infra HA is sized via
each managed block's own count (`database.managed.instances`, `messaging.managed.replicas`,
`keycloak.managed.instances`).

## Mixed — external DB, managed RabbitMQ, external OIDC

```yaml
spec:
  database:  { mode: external, host: pg.corp.internal, name: ilmdb, credentials: { secretRef: ilm-db } }
  messaging: { mode: managed, brokerType: rabbitmq, virtualHost: ilm, managed: { replicas: 3 } }
  # keycloak omitted → corporate OIDC configured in the app's Authentication Settings
```

Prerequisites scale with what is `managed`: here, only the RabbitMQ operators.

## Custom container registry

```yaml
spec:
  common:
    image: { registry: registry.mycorp.local, repository: ilm, pullSecrets: [mycorp-regcred] }   # all ILM components
  # per-component override (per field): auth: { image: { repository: my-auth-repo } }
  database:  { mode: external, host: pg.mycorp.local, name: ilmdb, credentials: { secretRef: ilm-db } }
  messaging: { host: rabbitmq.mycorp.local, virtualHost: ilm, credentials: { secretRef: ilm-messaging } }
```

For air-gapped *everything* (including the upstream operators + connectors) with zero
per-resource edits, use a cluster-level registry mirror (containerd/CRI-O mirrors, or
OpenShift `ImageDigestMirrorSet`).

## Prerequisites for `managed` mode

| Dependency set to `managed` | Upstream operator required |
|---|---|
| `database` / `pgBouncer` | CloudNativePG |
| `messaging` | RabbitMQ Cluster Operator + Messaging Topology Operator |
| `keycloak` | Keycloak Operator |

The operator **detects** these CRDs and gates the dependent feature gracefully: a missing
operator surfaces a non-fatal `…NotInstalled` reason on that dependency's adjunct condition
(`DatabaseReady` / `MessagingReady` / `KeycloakReady`) and the platform waits — it never fails,
and self-heals once the operator is installed. cert-manager + an ingress controller are needed
for a cert-managed `edge` regardless of mode. See the
[getting-started guide](../../platform.md) for the exact install commands.
